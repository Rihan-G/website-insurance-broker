Upload checklist — implemented in repo vs operator steps
===========================================================

Implemented (this codebase)
---------------------------
- Client vs staff upload paths; staff must pick a client before uploading.
- document_purpose (claim, renewal, id_proof, policy, other) on documents + Documents list + CSV export.
- New-version upload: optional row to replace; keeps logical file_name and increments version.
- Client-side magic-byte validation (uploadMagic.ts) plus safe storage file extensions.
- Parallel upload cap (4) in the browser.
- Edge Function document-ingest: JWT auth, ownership checks, per-minute rate limit (25 client / 60 staff),
  server magic-byte verification, SHA-256 (full file if ≤2MB else first 1MB + scope note), optional
  VIRUS_SCAN_WEBHOOK_URL stub, structured JSON logs, updates ocr_data / ocr_confidence / status.
- Storage RLS for voice/<user_id>/ on the documents bucket (00007).
- supabase/config.toml verify_jwt for document-ingest.

You still must run (operations)
--------------------------------
1. supabase db push (or apply migrations 00006, 00007) on each environment.
2. supabase functions deploy document-ingest
3. Create private bucket "documents" if missing; confirm file_size_limit suits your needs.
4. Point frontend .env at the real project (not localhost placeholder) for live uploads + ingest.

Production hardening (follow-up, not fully automatable here)
-------------------------------------------------------------
- Swap document-ingest OCR placeholder for Document AI / Textract / Vision API + durable job queue.
- True virus scanning integration (respond to webhook, quarantine objects).
- Column-level or trigger-based UPDATE policies if clients must PATCH metadata without Edge.
- WAF / CDN rate limits in front of Supabase for abuse beyond per-user ingest limits.
